# قوائم سماح حدّ القناة (ADR-069 · §6-2 · المرحلة 2)

كل ملف `<surface>.json` يمثل سطحًا واحدًا (تطبيق Mini App) وكل مدخل فيه يصف
مسارًا واحدًا يفتحه الحدّ لذلك السطح. الحارس `edge-allowlist-guard` (الفحص 28)
يقرأ هذه القوائم ويرفض أي انحراف عن الشفرة الفعلية أو عن قرار ADR-069 §2.8.

- الصيغة المطلوبة لكل مدخل: `{method, path, service, class, required_scopes, accepts_body, production_open, evidence_tests[]}` (+`blocked_until` لكل مدخل مغلق غير `O`).
- `class` من التصنيف §2.8 حرفيًا: `O` (ملكية بـ`obo`) · `P` (قراءة عامة) · `W` (تعتمد على `wua1`) · `N` (بلا ربط ملكية) · `ADM` (إدارة).
- قاعدة الفتح: `O` بدليل E-18 صريح للمسار نفسه والمستقبل `off`، وE-19 إن قبل **عقد** المسار جسمًا (`accepts_body` المقيس من الشفرة، لا الطريقة)؛ `P` بشقّي E-20 (معاملات مقيدة + المنشور فقط)؛ وكلاهما بمنح صريح لدور الحدّ في `PRODUCTION_GRANTS`. لا `W` قبل G-ENF، ولا `N` قبل حارس ملكية مختبر، ولا `ADM` قبل المرحلة 4.
- `required_scopes` تساوي بالضبط صلاحيات حارس المسار في الشفرة وفي اللقطة التاريخية، ومن كتالوج الخدمة المعتمد. و`service` تساوي وجهة اللقطة.
- `production_open: false` يعني أن المدخل مسجَّل للقياس ولا يُفتح للإنتاج.

الحقيقة الحالية: **كل المدخلات الـ29 مغلقة عمدًا** — أدلة E-18/E-19/E-20 الحقيقية تُكتب في الجزء الثاني (`app-edge-e2e`). الأبواب ورموزها وصيغة الدليل في [EDGE_ALLOWLIST.md](../../../docs/12-testing/EDGE_ALLOWLIST.md).
