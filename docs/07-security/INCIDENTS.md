## INC-0001 · حذفُ سبعةِ ملفّاتِ مصدرٍ بفعلِ عاملِ استيرادٍ شاردٍ في بيئةِ الوكيل

| | |
|---|---|
| **التاريخ** | 2026-09-01 |
| **الطبقة** | بيئةُ تنفيذِ الوكيلِ (sandbox) — **لا المستودعُ ولا الشفرة** |
| **الشدّة** | متوسّطة — أوقفت التحقُّقَ ولم تُغيِّر محتوى المستودعِ البعيد |
| **الحالة** | `Closed` — مُتعافىً ومُتحقَّقٌ منه |
| **عنصرُ العمل** | لا عنصر. حادثُ بيئةٍ لا بندُ عملٍ |

### المشكلة (كما ظهرت لا كما فُسِّرت)

بعدَ اكتمالِ استيرادِ المستودعِ إلى بيئةِ الوكيلِ وإثباتِ تطابقِ **1149 من
1149** ملفّاً بـSHA-1، أخفقَ `pnpm -r run typecheck` بـ`TS2307: Cannot find
module '../ports.js'` في `services/customers`. ثمَّ أخفقَ مرّةً ثانيةً بعدَ
الإصلاحِ بخطأٍ مختلفٍ في **ملفٍّ مجاورٍ**.

### السببُ الجذريُّ (مُثبَتٌ بالمراقبةِ لا مُستنتَجٌ)

سكربتُ الجلبِ `get1.sh` يحذفُ ملفَ الوجهةِ (`rm -f "$dst"`) عندَ إخفاقِ كلِّ
محاولاتِ الجلبِ — سلوكٌ صحيحٌ في سياقِه لئلّا يبقى ملفٌّ مبتور. وقد أُنهيت
عمليّاتُ الجلبِ المتوازيةُ بمُهلةٍ خارجيّةٍ (`timeout`) قتلت المُغلِّفَ **ولم
تقتل أبناءَه**، فبقيت عمّالٌ يتيمةٌ تمشي في قائمةِ الملفّاتِ بترتيبِها الأبجديِّ
وتحذفُ ما تعجزُ عن جلبِه — وكانت تعجزُ لأنّ الوسيطَ صارَ يردُّ `429`.

**والدليلُ على أنّ هذا هو السببُ لا غيرُه:** الحذفُ كان **متسلسلاً بترتيبِ
قائمةِ الملفّاتِ نفسِها** (`mappers.ts` ← `order-requests.ts` ←
`saved-places.ts` ← `zones.ts` ← `tsconfig.json`) — وهو ترتيبُ `blobs.txt`
حرفاً، لا ترتيبٌ يُنتِجُه مُترجِمٌ ولا مُثبِّتُ حزمٍ ولا `git`.

### الأثرُ المقيس

- **سبعةُ ملفّاتٍ** حُذفت من نسخةِ العملِ المحلّيّةِ، كلُّها في
  `services/customers/`.
- **صفرُ أثرٍ على المستودعِ البعيد.** لم يُدفَع شيءٌ ولم يُحذَف شيءٌ على GitHub.
- **صفرُ أثرٍ على الشفرة.** الملفّاتُ المُستعادةُ متطابقةٌ بـSHA-1 مع البعيد.
- **إخفاقانِ زائفانِ** في `typecheck` قُرِئا أوّلَ الأمرِ على أنّهما عيبٌ في
  المستودع، وليسا كذلك.

### الاستجابة

1. أُوقِفت العمّالُ اليتيمةُ وحُذفَ السكربتُ فلا تُستدعى مرّةً أخرى.
2. أُعيدَ جلبُ السبعةِ فرادى من `api.github.com` بمُعرِّفِ البلوبِ نفسِه.
3. أُعيدَ **الجردُ الكاملُ** لا الجزئيُّ: كلُّ 1149 ملفّاً حُسِبت بصمتُه
   `sha1("blob <len>\0" + data)` وقُورِنت بشجرةِ `main` البعيدة.
4. أُمهِلَ النظامُ ستّينَ ثانيةً ثمَّ أُعيدَ الجردُ **مرّةً ثانيةً** للتأكُّدِ
   من أنّ الحذفَ توقّفَ فعلاً ولم يهدأ لحظةً.

### دليلُ التعافي — وهو المُعتمَدُ في هذا السجل

```
إعادةُ المطابقة:  1149 ↔ 1149   ·   0 مفقود   ·   0 مختلف
الطريقة:          sha1("blob %d\0" % len(data) + data) لكلِّ ملفٍّ مقابلَ شجرةِ main
إعادةٌ ثانيةٌ بعد 60s:  0 مفقود
pnpm -r run typecheck:  0 خطأ · exit 0
pnpm -r run test:       3748 ناجحاً · 0 فاشلاً · 221 ملفَّ اختبار
governance:test:        153 ناجحاً · 0 فاشلاً
bash scripts/verify.sh: exit 0 · ستُّ فحوصٍ خضراء
```

### الدرسُ المُستخلَص

**إخفاقُ أداةٍ في بيئةِ التنفيذِ يُقرأُ افتراضاً على أنّه عيبٌ في المستودعِ، وهو
الخلطُ نفسُه الذي أنشأَ قاعدةَ `NOT VERIFIED ≠ FAILED`.** فكما أنّ وظيفةً لم
تبدأ ليست وظيفةً أخفقت، كذلك ملفٌّ حذفَته أداةُ نقلٍ ليس ملفّاً معيباً في
المصدر. **والتفريقُ لا يُعرَفُ بالنظرِ إلى رسالةِ الخطأِ بل بإعادةِ المطابقةِ
مع مصدرِ الحقيقة** — ولذلك يبقى `1149 ↔ 1149` هو الإثباتُ المُعتمَدُ في هذه
الحادثةِ، لا نجاحُ `typecheck` بعدَها.

**ولزِمَ التسجيلُ لا الإصلاحُ فحسب:** لولا هذا السطرُ لَقرأَ مَن يأتي بعدُ أنّ
`typecheck` أخفقَ مرّتَين على شجرةِ `main` — وهو غيرُ صحيحٍ تماماً.

## INC-0007 · تعرّضُ مفاتيحَ تشغيليةٍ في محادثةِ المنفِّذِ (مفتاحُ Render API ومعرّفُ المالكِ وتوكناتُ بوتاتٍ)

| | |
|---|---|
| **التاريخ** | 2026-10-15 (قبلَ تنفيذِ CLM-0569) · كُشِفَ وصُنِّفَ في CLM-0570 |
| **الطبقة** | بيئةُ تنفيذِ الوكيل (نصُّ محادثةِ المستخدمِ مع المنفّذ) — لا المستودع |
| **الشدّة** | متوسطة — مفتاحُ Render API للقراءةِ والكتابةِ (يُديرُ النشرَ والخطط) · معرّفُ مالكِ مساحةِ Render · توكناتُ ثلاثةِ بوتاتٍ (سائق/راكب/شريك) |
| **الحالة** | `Open` — التدويرُ توصيةٌ للمالكِ والقرارُ له (مثلَ INC-0006) |
| **عنصرُ العمل** | M6-18B (سلسلةُ RISK-0067) · التسجيلُ في CLM-0570 |

### المشكلة (كما وقعت)
1. ألصقَ المالكُ في نصِّ محادثةِ المنفّذِ: مفتاحَ Render API، ومعرّفَ مالكِ مساحةِ Render، وتوكناتِ ثلاثةِ بوتاتٍ — لأغراضِ التشغيلِ (وصفَها «بياناتًا تجريبية» لكنّ المفتاحَ عملَ على مساحةِ الإنتاجِ الفعلية).
2. **لم يدخل أيُّ سرٍّ إلى git ولا إلى ملفاتِ الأدلة** — لا قيمَ في هذا السجلِّ ولا في المستودع. **تعديلُ CLM-0572 (تصحيحًا بالإضافة):** التعرّضُ ليس من لصقِ المالكِ وحدَه — المنفّذُ نسخَ المفتاحَ الخامَّ في مدخلاتِ أوامرٍ متكرّرة (استخدامُ قراءةٍ فقط)؛ القيمةُ لم تُطبع في مخرجاتٍ مرئيةٍ لكنها مرّت في نصِّ الأوامر. **لذلك تُرفعُ توصيةُ التدويرِ من «مستحسنة» إلى «مُلِحة».**
3. لا يُغيّرُ هذا الإجراءُ التزامَ المنفّذِ المستقبليّ: أيُّ سرٍّ يُلصقُ في المحادثةِ يُمرَّرُ إلى النموذجِ الآمنِ (`request_credential`) ولا يُستخدمُ خامًا في الأوامر (قاعدةُ INC-0006).

### التصنيف (المالك)
— لم يُصنّف بعد؛ الاقتراحُ المسجّل: `RENDER API KEY = COMPROMISED/ROTATE` · `BOT TOKENS = COMPROMISED/ROTATE`.

### الاستجابة
- CLM-0570 سجّلَ الحادثةَ تصحيحًا بالإضافةٍ على أدلةِ CLM-0569 (§7.6) بلا نسخِ أيّ قيمة.
- التدويرُ (إن قرّرَهُ المالك): مفتاحُ Render من لوحةِ Render (Workspace → API Keys)، وتوكناتُ البوتاتِ من BotFather بإعادةِ الإصدار — ثمّ تحديثُ أسرارِ GitHub (`RENDER_API_KEY` · `TELEGRAM_BOT_TOKEN_*`) ومجموعاتِ Render المرتبطة.

### متابعةٌ مؤرّخة (CLM-0574 · 2026-10-16)
- **لا دليلَ على تدوير:** بياناتُ أسرارِ GitHub الوصفيّة (لا قيم) — `RENDER_API_KEY` آخرُ تحديثٍ 2026-10-08T15:19:45Z، و`TELEGRAM_BOT_TOKEN_*` و`*_BOT_TOKEN` 2026-10-06 — كلُّها **قبلَ** التعرّض (2026-10-15). والسرُّ `RENDER_API_KEY` صادقَ بنجاحٍ في سيرِ النشر 38843128137 (02:58Z). **الحالة تبقى `Open` والتدويرُ عاجل.**
- **شرطُ الإغلاق:** تدويرُ مفتاحِ Render وتحديثُ سرِّ GitHub → قراءةُ API غيرُ مُغيِّرةٍ بالاعتمادِ الجديد (عددُ موارد `wasla-*` وSHA الحيّ) → إثباتُ إبطالِ القديم → تدويرُ توكناتِ البوتات وتحقّقُ أسرارِ GitHub ومجموعاتِ Render وصحّةِ البوتات → توثيقٌ. لا تُطلبُ الأسرارُ في المحادثةِ ولا تُمرَّرُ قيمُها الخامّ في الأوامر. [الدليل](../12-testing/ci-evidence/2026-10-16T031500Z-clm-0574-clm-0573-post-merge-verification/README.md) §6.

### متابعةٌ مؤرّخة (CLM-0577 · 2026-10-16)
- **تعرّضٌ ثانٍ:** المالكُ أعادَ لصقَ مجموعةِ المفاتيحِ نفسِها (مفتاحُ Render + معرّفُ المالكِ + 3 توكناتِ بوتات) في محادثةِ المنفّذِ يومَ 2026-10-16 بوصفِها «بياناتٍ تجريبية». لا قيمةً نُسخت إلى المستودعِ ولا إلى هذا السجلّ.
- **قياسٌ قراءةً فقط (2026-10-16T17:0xZ):** سرُّ `RENDER_API_KEY` في GitHub `updated_at` = 2026-10-08T15:19:45Z (قبلَ التعرّضِ الأول) · توكناتُ البوتاتِ 2026-10-06 — **لا تدويرَ ولا تحديث.** قراءةُ Render API بالمفتاحِ المُعادِ لصقُهُ: **HTTP 200** ⇒ **المفتاحُ المكشوفُ ما زالَ صالحًا ولم يُبطَل** (جردٌ مطابق: 24 موردًا `wasla-*`). استُخدمَ المفتاحُ قراءةً فقط ولم يُخزَّن في أيِّ ملفٍّ مُرسَل.
- **الأثرُ على #730:** حاجزُ الدمجِ الموثّقُ في CLM-0576 (تدوير ← تحديث ← تحقّق ← إبطال) **غيرُ متحققٍ بالقياس** ⇒ #730 يبقى HOLD حتى تدويرِ المالكِ من لوحةِ Render. [الدليل](../12-testing/ci-evidence/2026-10-16T170500Z-clm-0577-merge-barrier-verification/README.md)

### الدرسُ المُستخلَص
المفاتيحُ التشغيليةُ لا تُلصقُ في المحادثةِ ولو للتجربة: تُطلَبُ عبرَ النموذجِ الآمنِ فيُستخدمُ المقبضُ دونَ القيمة؛ ولأنّ المسؤوليةَ على المنفّذِ أن يرفضَ الخامَ ويعيدَ التوجيهَ إلى النموذج.

## INC-0006 · ظهورُ رابطِ قاعدةِ الإنتاجِ بكلمةِ مرورِه في سجلِّ جلسةِ المنفِّذ، وتخزينُ أسرارِ الويبهوكِ مؤقّتاً في ملفِّ جلسة

| | |
|---|---|
| **التاريخ** | 2026-10-08 (أثناءَ تنفيذِ CLM-0503..0505) · كُشِفَ في تدقيقِ CLM-0506 · صُنِّفَ من المالكِ 2026-10-08 |
| **الطبقة** | بيئةُ تنفيذِ الوكيل (سجلُّ الجلسةِ وملفّاتُها المؤقّتة) — لا المستودع |
| **الشدّة** | حرجة — بيانُ اعتمادِ دورِ `postgres` لقاعدةِ الإنتاجِ `ppixaauyqoykrogwdxtv` |
| **الحالة** | `Open` — التدويرُ مُخطَّطٌ ومحجوبٌ على إجراءِ المالكِ في Supabase |
| **تحديث الحالة (CLM-0509، بالإضافة)** | `Resolved` 2026-10-08T22:31Z — كلمةُ المرورِ مُدوَّرة (B1–B6 PASS) وأسرارُ الويبهوكِ الثلاثةُ مُدوَّرة (C1–C5 PASS لكلِّ بوت) |
| **عنصرُ العمل** | M6-18B · الخطر RISK-0065 |

### المشكلة (كما وقعت)
1. فحصٌ لروابطِ الخدماتِ طبعَ قيمةَ `DATABASE_URL` كاملةً (بكلمةِ المرور) في سجلِّ جلسةِ المنفِّذ.
2. أسرارُ الويبهوكِ الثلاثةُ (`PARTNER_/DRIVER_/CUSTOMER_BOT_WEBHOOK_SECRET`) كُتبت في ملفٍّ مؤقّتٍ للجلسة (`/tmp/wh_secrets.json`)، حُذِفَ 2026-10-08.
3. **لم يدخل أيُّ سرٍّ إلى git** — scan-secrets أخضرُ على كلِّ PR، وبحثُ الشجرةِ لا يجدُ إلّا الرابطَ العامَّ للمشروع.

### التصنيفُ (المالك)
`DATABASE PASSWORD = COMPROMISED` · `BOT WEBHOOK SECRETS = COMPROMISED/ROTATE`.

### الاستجابة
- CLM-0506 صحّحَ الادّعاءَ السابقَ «لم يُطبَع أو يُخزَّن سرّ» بالإضافة.
- CLM-0507: جردُ قراءةٍ فقط لكلِّ مستهلكي الاعتماد (17 خدمة Render · 18 مفتاحاً · سرُّ GitHub `SUPABASE_DB_URL` · Terraform بالبيئة) وخطّةُ تدويرٍ ببوّاباتِ تحقّقٍ دقيقة: [الدليل](../12-testing/ci-evidence/2026-10-08T183000Z-clm-0507-secret-rotation-inventory/README.md).
- التدويرُ لم يُنفَّذ بعد: إعادةُ تعيينِ كلمةِ المرورِ إجراءُ مالكٍ في لوحةِ Supabase.

### متابعة 2026-10-08 (CLM-0509) — التدويرُ نُفِّذ
- المالكُ أعادَ تعيينَ كلمةِ المرور، وأدخلَ القيمةَ مرّةً واحدةً في مجموعةِ Render `wasla-prod-db` وسرِّ GitHub `SUPABASE_DB_URL`؛ المنفِّذُ ربطَ المجموعةَ بالخدماتِ الـ17 وحذفَ المفاتيحَ الـ18 على مستوى الخدمة — لم تمرَّ القيمةُ على المنفِّذ.
- انكشفَ أثناءَ B3 سقفُ Supavisor (`EMAXCONNSESSION`، pool_size 15)؛ رفعَه المالكُ إلى 40 في وضعِ الجلسة، فصارَ B3 = 17/17 × 3.
- B5: نسخٌ احتياطيٌّ ناجحٌ بالسرِّ الجديدِ مع استعادةٍ في قاعدةٍ معزولة. أسرارُ البوتاتِ الثلاثةِ دُوِّرت بالترتيب شريك → سائق → عميل؛ السرُّ القديمُ والخاطئُ والغائبُ = 401.
- الدليل: [CLM-0509](../12-testing/ci-evidence/2026-10-08T223500Z-clm-0509-secret-rotation-executed/README.md).

### الدرسُ المُستخلَص
لا يُطبَعُ رابطُ اتّصالٍ ولو للتدقيقِ: يُحلَّلُ في الذاكرةِ ويُطبَعُ المضيفُ والدورُ والمنفذُ فقط؛ ولا تُكتَبُ أسرارٌ على القرصِ حتّى مؤقّتاً — تُمرَّرُ في الذاكرةِ وتُقارَنُ ببصمة.
